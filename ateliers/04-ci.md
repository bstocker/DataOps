# Atelier 4 — Le robot de vérification (20 min)

🎯 **Objectif** : voir un robot GitHub relancer **vos tests à chaque envoi**, et le regarder attraper une erreur.

---

## 🧠 L'idée en une phrase

C'est l'**intégration continue** (ou **CI**) : à chaque `push`, un robot de GitHub (appelé *GitHub Actions*) prend un ordinateur neuf, installe le projet et lance les tests. Si quelqu'un casse quelque chose, l'équipe est prévenue **tout de suite**, avant que l'erreur n'arrive chez le client.

```
 vous ──push──► GitHub ──► 🤖 robot : installe, lance les tests ──► ✅ ou ❌
```

---

## 📋 Étapes

### 1. Regarder la CI verte

Sur github.com, dans **votre fork**, onglet **Actions**. La dernière exécution (après l'atelier 3) doit être **verte ✅**.

> Elle est rouge ? Lancez `./verifier.sh 3` dans le Codespace, corrigez, puis refaites **commit + push**.

Cliquez sur l'exécution, puis sur **Tests de qualité des données** : vous voyez exactement ce que le robot a fait, ligne par ligne.

> 💡 *Curieux ?* La recette suivie par le robot est dans le fichier `.github/workflows/ci.yml`. Vous n'avez pas besoin de le modifier.

### 2. Casser volontairement

1. Dans `src/pipeline.py`, ajoutez un `#` devant la ligne du **TODO 2.3** :

   ```python
       # df = df[(df["quantite"] > 0) & (df["prix_unitaire"] > 0)]
   ```

2. **commit + push** avec le message `Casse volontaire`.
3. Sur github.com, onglet **Actions** : une nouvelle exécution démarre (rond jaune 🟡). Attendez 1 à 2 minutes.
4. Elle devient **rouge ❌**. Cliquez dessus, puis sur **Tests de qualité des données** : quel test a sonné l'alarme ?

### 3. Réparer

1. Dans `src/pipeline.py`, **enlevez le `#`** que vous avez ajouté.
2. Vérifiez sur votre Codespace : `python -m pytest -v` → tout est vert.
3. **commit + push** avec le message `Réparation`.
4. Dans **Actions**, la nouvelle exécution redevient **verte ✅**.

---

## ✅ Vérification

```bash
./verifier.sh 4
```

Objectif : **3 / 3**. Le vérificateur lit l'historique de votre onglet Actions : il doit y voir **vert → rouge → vert**.

---

## 🏁 Fin de l'atelier

1. Lancez le bilan complet :

   ```bash
   ./verifier.sh tout
   ```

2. Faites un dernier **commit + push** (message : `Rendu final`).
3. Sur github.com, onglet **Actions** → dernière exécution → section **Summary** : vous y voyez votre note.
4. Arrêtez votre Codespace : [github.com/codespaces](https://github.com/codespaces) → `…` → **Stop codespace**.

🎉 **Bravo ! Vous avez construit une vraie chaîne DataOps : des données vérifiées, nettoyées, testées et surveillées par un robot.**
